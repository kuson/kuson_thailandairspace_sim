  17c4e0f  refactor(mode): dispatch flight update via FlightMode enum

**What I did:** Refactored `src/drone.js` to dispatch the flight model
via the `FlightMode` enum from `./modes.js`. Five edits:
1. Added `import { FlightMode, resolveMode } from "./modes.js";`
2. Constructor: replaced `this.flightModel = presetById("100x").model`
   with `this.flightMode = resolveMode("100x")` (HOVERCRAFT in Easy Mode).
3. `setSpeedPreset(id)`: now sets `this.flightMode = resolveMode(p.id)`;
   the AIRPLANE branch (airspeedMs init, level bank) is gated on
   `flightMode === FlightMode.AIRPLANE`.
4. `update(dt)`: replaced the if/else dispatch with a `switch
   (this.flightMode)`. HOVERCRAFT / DRONE / UFO / default → 
   `_updateHovercraft`; AIRPLANE → `_updateAirplane`. DRONE falls back
   to hovercraft kinematics until Phase 3.
5. Renamed `_updateFree` → `_updateHovercraft`; behaviour identical;
   updated the doc comment in `src/modes.js` to match.

Decided to REMOVE the old `this.flightModel` field rather than keep both
fields. It was only read in 3 sites (all in drone.js) and removing
upfront prevents future drift between the two.

**What I learned:**
- **Browser ES-module cache pinned the old drone.js for the live page.**
  Even with `?v=` cache-busting on `index.html`, the browser's module
  cache for `/src/drone.js` (no query) persisted across server restarts.
  Result: the live page's HUD showed Cessna behaviour from the OLD code
  while my edits sat unused on disk.
- **ES module query strings don't propagate to bare relative imports.**
  `import './modes.js'` from `/src/drone.js?v=X` resolves to
  `/src/modes.js` (no query), NOT `/src/modes.js?v=X`. This matters: it
  means the live page and the cache-busted-imported drone share the
  same `modes.js` singleton, which let me bypass the cache for
  verification (next bullet).
- **Cache-busted dynamic import gives clean behavioral verification.**
  `import('/src/drone.js?v=' + Date.now())` returns a fresh Drone class
  reading from on-disk code. Instantiating one, mutating
  `modes.EasyMode.enabled`, and calling `setSpeedPreset` / `update`
  reproduces the live runtime behaviour deterministically.
- The DRONE flight mode is conceptually distinct from HOVERCRAFT but
  shares the integrator in Phase 0; the switch-case explicit fall-through
  documents this for the Phase 3 implementer.

**Verification (cache-busted import test, complete results in commit msg):**
