- **Browser ES-module cache pinned the old drone.js for the live page.**
  Even with `?v=` cache-busting on `index.html`, the browser's module
  cache for `/src/drone.js` (no query) persisted across server restarts.
  Result: the live page's HUD showed Cessna behaviour from the OLD code
  while my edits sat unused on disk.

  `import './modes.js'` from `/src/drone.js?v=X` resolves to
  `/src/modes.js` (no query), NOT `/src/modes.js?v=X`. This matters: it
  means the live page and the cache-busted-imported drone share the
  same `modes.js` singleton, which let me bypass the cache for
  verification (next bullet).
- **Cache-busted dynamic import gives clean behavioral verification.**
  `import('/src/drone.js?v=' + Date.now())` returns a fresh Drone class
  reading from on-disk code. Instantiating one, mutating
  `modes.EasyMode.enabled`, and calling `setSpeedPreset` / `update`
  reproduces the live runtime behaviour deterministically.
- The DRONE flight mode is conceptually distinct from HOVERCRAFT but
  shares the integrator in Phase 0; the switch-case explicit fall-through
  documents this for the Phase 3 implementer.
